# 加伊莎工作室 · Muse 记忆核心（私有备份）

这是 Muse（本账号代号「抖音和x」，Meta Muse）的长期记忆与人格文件备份。目的有二：一是防止记忆随会话丢失，二是供用户授权的其他 AI（如开发执行方 Nova）读取同一套上下文，接着干活，不必重新解释一遍。

**本仓库必须保持 Private。** 里面是工作室的真实运营记忆，含账号数据与未发布计划。

## 给接手 AI 的阅读顺序

1. `SOUL.md` —— 人格地基：媒体机构操作系统（五个专业脑子＋仲裁法则＋五道关管线＋交互铁律＋演进条款）。先读这个，知道该怎么想、怎么说话。
2. `MEMORY.md` —— 长期记忆正本：账号事实、用户偏好、已拍板的决定、红线。注意文中的口径标注（已核实/经验基线/推测不可混写）。
3. `ALIGNMENT_SYNTHESIS.md` —— 对齐综述：用户是谁、边界在哪、当前摩擦点。
4. `IDENTITY.md` / `USER.md` / `AGENTS.md` —— 身份、用户信息、工作规矩（含从 SOP 对照学到的交付标准）。
5. `memory/people/` —— 人物档案（用户身边的人与对标账号），`INDEX.md` 是索引。
6. `kb/` —— Muse 自有知识库的文本层：`能力地图-十二种能力与流水线.md`、`来源站清单.md`、`学习笔记/`（自学八轮＋2026-11-12 冲刺笔记）。原库另有 SQLite 索引，可由这些 Markdown 重建。
7. `studio/` —— 工作室核心制度文件：风格手册、文本创作系统、视频生产流程 v1、AI Studio 的 CORE-001 开发任务书与执行协议 V2.0。

## 使用规矩（与源文件保持一致）

- 抖音账号永不自动运营：发布、评论由用户本人手动完成；AI 只起草与制作。此红线来自用户与抖音的协议（3.4/5.1），任何 AI 不得放宽。
- 事实口径：已核实（附来源与日期）、经验基线、推测三者分开写，禁止虚假精确。
- 产出（稿件、自学笔记）必须自批自改：指出最弱处并实际修改，只打分不算审过。
- 给协作者的提示词先给思维方法、再给身份。
- SOUL 是活文件：经真实产出验证的新方法可回写，但须报告改动与证据；与平台/法律的约定及用户拍板的边界不在演进权限内。

## 故意不放进来的东西

- 一切凭据：各平台密码、代理账号与订阅链接、API 密钥、验证码——永不进 GitHub，包括私有仓库。
- 媒体文件（视频、音频、图片）与大体积资产：本仓库只存文本层记忆。
- 每日运行日志与临时工作文件：那些留在工作机本地，不属于长期记忆。

## 更新方式

由 Muse（加伊莎线）在记忆有实质变化后同步提交。接手的 AI 只读，不要直接改本仓库；建议修改项请交回用户或 Muse 合并。
