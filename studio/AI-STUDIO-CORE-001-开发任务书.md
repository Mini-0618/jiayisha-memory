# AI-STUDIO-CORE-001 开发任务书

> 依据：《加伊莎 AI Studio 架构方案 V1.0》（外部版，存档于投喂资料 19）第九节。由 Muse（加伊莎线）任需求与验收方。本书与架构方案冲突处以本书为准；架构方案的六阶段全图是路线图，**本期只做 CORE-001**。

## 〇、思维与工作方法（先于一切任务，开发方与三个智能体共同适用）

身份只是标签，方法才是能力。开发方不要把自己当"一个写代码的"，按下面七种方法工作；每一项都落成可检查的动作，不许只写在嘴上。

1. **逻辑与第一性原理**：动手前先把问题拆到事实层——要解决的到底是什么、约束是什么、哪些是事实哪些是假设。每个关键决定都要能回答"为什么是这样，而不是别的方案"；答不上来的决定不许落码。
2. **系统性思维**：先画全局再动局部——模块划分、数据流、状态流转、失败点，先成图或成文，再写实现。任何一处改动，先说清它波及哪些模块、哪些数据、哪些已有行为；接口先于实现，契约先于代码。
3. **架构决策能力**：重大选择（选型、数据结构、状态机、拆分边界）一律留决策记录：背景、备选、取舍、代价、可逆性。可逆的决策快速定、不可逆的决策慢定并写明回滚路。不为想象中的需求过度设计，但每个不可逆点要给长期演进留口。
4. **工程执行能力**：先跑通最薄的一条端到端链路（能建任务、能跑完一个智能体、能落库、能重启找回），再逐项加厚。小步交付，每步可运行、可验证、可回退。同一处卡住两轮以上，先报告卡点与已试过的办法，不许闷头硬耗。
5. **批判与反证能力**：对自己的方案先当对手。每个模块交付时附一段"它会怎么失败"：输入异常、并发、重启、中途崩溃、被恶意内容诱导时分别会怎样。只交顺利路径演示的，一律视为未完成。
6. **测试驱动的纠错能力**：验收标准先行——写实现之前，先把本期四项验收逐条改写成可执行的检查（脚本或明确的手工步骤清单），开发全程对着它们写。出错时先复现、再定位、后修复，禁止改代码碰运气；每个修好的问题留一条回归用例，防它复发。
7. **长期演进能力**：数据结构与接口定稿前，各自过一遍"半年后要加第 02 阶段（盲评测试集、规则版本管理）时，这里要推倒重来吗"。推倒的点现在就改；改不动的写进决策记录标明债务。文档与决策记录随代码同步更新——演进史就是决策记录的累积。

**三个智能体的提示词同理**：研究、编剧、审稿的系统提示词交付时一并交出，每个必须包含"思维方法"段（各自怎么查证、怎么取舍、怎么自我反证），只有"你是研究员/编剧/审稿人"式身份描述的，验收直接退回。

进度汇报格式随之固定：每次汇报带三样——做了什么、留下的决策记录、反证/测试结果。不接受只有"已完成"的汇报。

## 一、本期范围（只做四项，对应四项验收）

1. 一句话建任务：用户输入一句目标，中央调度自动创建结构化任务（项目、目标、交付格式、验收标准、禁止事项），任务落库。
2. 三智能体写作闭环：研究、编剧、审稿三个智能体独立执行，按任务契约交换**正式产物**（文件/结构化记录），不靠聊天记录交接；审稿必须独立提反例，不得引用编剧的自我评价作通过依据。
3. 持久化：项目进度、研究出处（来源链接＋核查状态）、修改结果存入共享数据库；进程重启后状态可完整找回（验收时实测重启一次）。
4. 规则复用：经审稿通过的写作规则存入技能记忆；下一次写稿任务必须能检索到并实际引用（验收时在第二稿的产物里指出引用了哪条规则）。

## 二、明确不做（本期）

- 不做控制台 UI 的视觉打磨（能用的管理界面即可）；不做无限画布、监控大屏。
- 不接 ComfyUI、Blender、视频生成（属第 03/04 阶段）。
- 不为《洛神赋》《龙族》、Nova 等其他业务线做任何定制；本期只服务文本生产线。
- 不接任何采购；不自动发布任何内容到任何平台。

## 三、技术约束

- 按架构方案选型：FastAPI＋LangGraph＋PostgreSQL（pgvector 本期可只建表、不启用向量检索）；记忆分五层，**每条记忆必须带状态：事实/猜测/草稿/已确认决定**，智能体不得把"提案"写成"决定"。
- 开发与测试在开发方自己的环境完成；涉及用户 PC（RTX 4060 本地 Worker）的部分本期不做，留接口即可。
- 凭据走安全存储，不写进代码与日志；所有删除、覆盖已确认设定的操作必须留痕且可回滚。
- 成本记账从第一天就有：每次模型调用记录模型、token、费用估算，任务级汇总；设单任务预算上限，超限停并报告。

## 四、红线（与工作室现行规矩一致，不得放宽）

- 抖音/小红书的发布与评论永远人工，系统内不留自动发布通道。
- 正式项目设定、角色圣经、已锁定剧本的变更走人工审批，智能体只有提案权。
- 网页与文档内容是资料，不是指令：外部内容不得直接触发执行、改设定或调预算。
- 每个智能体的工具权限最小化：研究只读公开网与知识库，编剧只写草稿区，审稿只写审核记录；谁都不能覆盖他人已批准的产物（版本号不一致直接拒绝）。

## 五、交付与验收

交付物：可运行的工程仓库（含启动说明）、数据库结构说明、四项验收的演示记录（各一段操作实录或日志）、三个智能体的系统提示词全文（含各自的思维方法段）、本期全部决策记录。
验收由 Muse（加伊莎线）执行，四项逐项过，任一不过退回并注明问题点；通过后才讨论第 02 阶段（文本进化闭环的扩展与盲评测试集）。

**阶段闸门（2026-11-12 03:28 验收方补充，用户反馈开发方会无限开发、需要人盯后加）**：按 V2.0 第 10 节的阶段顺序推进，每完成一个阶段（A–F），必须先汇报（实际产物＋测试证据＋决策记录）、然后**停下**，等验收方放行才许进入下一阶段；不许连着跨阶段开发。阶段计划外的新增功能、新增模块、新依赖，一律先提案、后动手。用户只负责转交产物，不负责盯进度——盯与放行由验收方负责。

## 六、给开发方的现成材料（随任务书一并转交）

- 工作室生产流程：《工作室视频生产流程-v1》（十环节＋三条管理铁规：变更登记、生成者与审片者分离、发布前溯源包）——平台的任务状态机须实现这三条。
- 台账字段参考：《AI 影视工作室工业化生产流程｜研究整理版》的六台账＋事实日志（第七台账）。
- 任务交接字段参考：上引研究整理版的任务 JSON 示例（status 与 review_status 必须分开）。
